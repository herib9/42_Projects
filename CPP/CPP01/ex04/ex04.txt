1. LA FUNCION LOGICA: mySed

Aquí es donde ocurre la transformación del texto. No trabajas con archivos todavía, solo con "memoria" (strings).

std::string mySed(std::string content, const std::string &s1, const std::string &s2)
{
    if(s1.empty()) // Protección: si lo que buscamos es nada, no hacemos nada
        return content;

    std::string result = "";
    size_t      pos = 0;
    size_t      last_pos = 0;

    size_t pos:
Guardará la posición donde encontremos s1.

    last_pos:
Es el "punto de lectura". Nos dice desde dónde tenemos que seguir buscando para no entrar en un bucle infinito.


    while((pos = content.find(s1, last_pos)) != std::string::npos)
    {
        result.append(content, last_pos, pos - last_pos); // 1. Copia lo que NO cambia
        result = result + s2;                             // 2. Pega la palabra nueva
        last_pos = pos + s1.length();                     // 3. Salta sobre la palabra vieja
    }

    find(s1, last_pos):
Busca la palabra s1 a partir de donde nos quedamos la última vez.

    std::string::npos:
Es una constante que significa "No se ha encontrado nada". El bucle sigue mientras haya coincidencias.

    append: 
Copia el trozo de texto original que hay antes de encontrar la palabra a sustituir.

📝 Puntos críticos para tu defensa:

    ¿Por qué no usar std::string::replace?: 
Porque la función miembro de string suele dar problemas si la longitud de s1 y s2 es diferente (puede mover el índice de forma inesperada). Tu método de "ir construyendo un nuevo string" (result) es mucho más seguro y profesional.

    Gestión de errores: 
Es obligatorio comprobar si el archivo existe (is_open()) y si el número de argumentos es correcto (ac != 4).

    Fugas de memoria: 
En este ejercicio no hay new, por lo que no hay delete. Todo se limpia automáticamente al salir de la función porque usas objetos del Stack.

    Buffer: 
Al usar stringstream, estás leyendo el archivo completo a memoria. Esto es eficiente para archivos normales, aunque si el archivo fuera de varios Gigabytes, tendrías que leerlo por trozos (buffers).
